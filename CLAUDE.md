# WAVEBREAK — правила для Claude (читать в начале каждой сессии)

Над проектом работают двое (владелец и коллега), каждый со своим Claude на своём ноутбуке.
Всё, что нужно знать, лежит в этом репозитории — не в памяти чата и не в локальных файлах.

## 1. Одна ветка, всегда свежая

- Рабочая ветка — **`app-main-sync`**. Не `main`, не `app`, не `dev`, не ветки `claude/*`.
- **Первым делом в каждой сессии:** `git switch app-main-sync && git pull --rebase origin app-main-sync`.
  Перед сборкой и публикацией — то же самое. Если не получается подтянуть — остановиться и
  сказать человеку, не работать со старой копией.
- Каждое изменение — коммит и `git push origin app-main-sync` сразу, плюс строка в
  `CHANGELOG.md` (раздел «Не выпущено»). Незапушенная работа для второго человека не существует.
- Если пуш не проходит (403, нет доступа) — сказать об этом человеку сразу, не копить коммиты.

## 2. Выпуск обновлений — только скриптом

```bash
tools/release/release.sh check     # всё ли готово на этой машине
tools/release/release.sh build     # релиз + откат, Android и Windows (или: build android)
tools/release/release.sh stage     # загрузка, ссылки для проверки на телефоне/ПК
tools/release/release.sh publish   # только после «публикуй» владельца
```

Подробно — навык `/release` (`.claude/skills/release/SKILL.md`). Вручную не собирать и не
выкладывать: скрипт сам проверяет ветку, номера, боевые параметры (без заглушек), подпись,
собирает откат и ведёт общую историю `tools/release/releases.json`.

Первая настройка машины: `docs/BUILD-MACHINE-SETUP.md`, затем
`cp tools/release/local.env.example tools/release/local.env` и поправить пути.

## 3. Чего не делать

- Не собирать для пользователей без 4 боевых `--dart-define` (скрипт делает это сам).
- Не переиспользовать номера сборок; Windows-версия — три числа (`1.0.12`, не `1.0.11.1`).
- Ключ подписи, пароли, SSH-ключи, токены, `.env.pilot` — никогда в git и в чат.
- Сайт раздаёт файлы из папки на хосте (`.../wavebreak-web/public/downloads`, подключена к
  контейнеру только на чтение). В контейнер файлы не копировать.
- Не возвращать logrotate для логов Docker (`copytruncate` ломал `dockerd`, 05.10).
- На серверах — только чтение без явного «ок» владельца; публикация — только после «публикуй».
- Фиксы, не проверенные на устройстве, так и помечать.
